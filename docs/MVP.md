# MVP 로드맵 / 할 일 (본인 트랙)

**본인 담당 = order · inspection · product 도메인 + 검색** 의 작업 목록·진행 상태를 관리하는 문서다.

- 전체 백로그·2인 분담·팀원(결제/정산/알림) 작업 → [`BACKLOG.md`](./BACKLOG.md) · GitHub #29
- 무엇을 만드는가(기능·플로우) → [`FEATURE_SPEC.md`](./FEATURE_SPEC.md) · 제품 방향 → [`PRODUCT_PLAN.md`](./PRODUCT_PLAN.md)
- 진행 흐름: 이슈(`enhancement`) → 브랜치 → PR(`Closes #N`) · 완료 조건: **테스트 포함**([TEST.md](./TEST.md))
- 상태 표기: `[ ]` 대기 / `[~]` 진행 중 / `[x]` 완료 · 각 항목 뒤 `(BACKLOG-ID · 우선순위)`

> **분담 컨셉**: 본인은 **이벤트를 "발행"하는 축**(상품·검수), 팀원은 **"구독"하는 축**(결제·정산·알림). 접점은 **도메인 이벤트 계약 하나**뿐 → 합의 후 병렬 진행.

## 공유 접점 (팀원과 먼저 합의)

- **도메인 이벤트 계약** (`A1`) — `InspectionPassed`/`InspectionFailed` payload + 주문 상태변경 이벤트 스키마. **본인이 발행 → 팀원이 정산(STAB-5)·알림(NOTI-1)으로 구독.** 이 프로젝트의 유일한 강결합이라 **가장 먼저 확정**.
- 상품 필드(`PROD-2`) ↔ 검수 리포트(`TRADE-1`) 데이터 정합 (둘 다 본인).

## 권장 진행 순서

```
STAB-1(재고버그) → STAB-6(RBAC) → PROD-1·PROD-2(이미지·필드)
→ PROD-3(검색 ★) → PROD-4·PROD-5(카테고리·찜)
→ TRADE-1·OPS-1(검수리포트) → TRADE-6
→ (Phase 5) PROD-6·7 · TRADE-4·5 · 공용
```

- **선행 합의**: 이벤트 계약(A1)은 STAB-5/NOTI 착수 전 팀원과 확정.
- **포트폴리오 포인트**: STAB-1(동시성/불변식) · STAB-6(인가) · PROD-3(검색 인프라) · TRADE-1(도메인 설계) 를 "왜/트레이드오프"까지 설명할 수 있게.
