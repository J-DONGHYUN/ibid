# 제품 기획서 (Product Plan)

> 이 문서는 프로젝트의 **방향·정체성·범위**를 정의한다. "무엇을 만드는 기능인가"는 [`FEATURE_SPEC.md`](./FEATURE_SPEC.md), "언제/어떤 순서로"는 [`MVP.md`](./MVP.md)에서 다룬다.

## 0. 프로젝트 목표 (가장 중요)

이 프로젝트의 1차 목표는 **기술적 성장의 증명**이다. 사용자 유치·기능 완성도가 아니다.

- **대용량 데이터를 가정**하고, **부하테스트(k6)로 병목을 찾아 성능을 개선**한다 (인덱스·쿼리 튜닝·캐싱·비동기).
- **AWS에 배포**해 클라우드 인프라(EC2/RDS/ElastiCache/S3/ALB 등)를 직접 다룬다.
- 관측성(메트릭·분산추적)으로 **개선 전/후를 수치로** 보여준다.

> "검수 에스크로 기반 **일반 중고 거래 마켓**"은 이 기술들을 담는 **도메인 그릇**이다. 따라서 제품 기능(커뮤니티·제품 알림·검수 리포트 심화·결제 정합성·수익 모델 등)은 대부분 **범위 밖**이다. **결제는 현 시점에서 종료**하며 정합성 추가 작업은 하지 않는다. RBAC·동시성 같은 **기술 기반기는 유지**한다.

## 1. 한 줄 정의 (도메인 그릇)

**"검수 에스크로 기반 중고 거래 플랫폼" — 모든 거래를 배송으로 진행하고 플랫폼이 검수해 안전을 보장하는 일반 중고 마켓.**

- 거래 방식: **고정가 즉시구매** · **전 거래 배송**(직거래 없음)
- 검수 범위: **전 거래 강제 검수** (모든 거래가 검수 에스크로 통과)
- **배송비**: 결제 시 합산되어 **플랫폼이 수취·관리**(판매자 정산 미포함)
- 카테고리: **일반 중고**(의류·잡화·전자기기 등) · 핵심 가치: **안전·품질 보증**

## 2. 문제 정의 (Why)

중고 전자기기(스마트폰·노트북·태블릿 등) 거래는 금액이 크고 상태 편차가 심해, 기존 개인 직거래(중고나라·번개장터·당근)에서 다음 피해가 반복된다.

- **사기**: 입금 후 미배송, 가짜 상품, 벽돌(빈 박스) 배송
- **상태 불일치**: 설명과 다른 하자 — 액정 멍, 배터리 성능 저하, 침수 흔적
- **정품/이력 문제**: 리퍼·모조품, **통신사 잠금·분실/도난 등록(IMEI) 단말**, 약정/개통 상태 불명
- **분쟁**: 받은 뒤 문제를 발견해도 되돌릴 방법이 없음

→ 구매자는 "**믿고 살 수가 없고**", 판매자는 "**정상 물건인데도 사기꾼 취급**"받는다. 이 신뢰 공백을 **플랫폼 검수 + 에스크로**로 메운다.

## 3. 타겟 사용자 (Who)

- **구매자**: 새 제품보다 싸게 사되 **사기·하자 걱정 없이** 사고 싶은 사람. (가격 민감 + 안전 중시)
- **판매자**: 쓰던 전자기기를 **제값 받고 안전하게** 팔고 싶은 사람. 사기꾼 의심·네고·직거래 약속 스트레스를 피하고 싶음.
- **플랫폼(우리)**: 검수 센터를 운영하며 양측 사이에서 **신뢰를 대행**하고 수수료를 얻는다.

## 4. 핵심 가치 제안 (Value)

**"정품·품질 보증"** 을 최전면에 세운다.

> 이 플랫폼에서 산 중고 전자기기는 **정품이고, 설명대로 작동하며, 잠금·분실 이력이 없다** — 플랫폼이 검수로 보장한다.

부수 가치: 에스크로로 **돈 떼임·미배송 걱정 제거**(안전거래)가 자연히 따라온다. 다만 마케팅 1순위 메시지는 **정품·품질 보증**.

## 5. 핵심 거래 흐름 (What) — 현재 구현과 매핑

이미 구현된 주문 상태머신이 곧 이 제품의 핵심 흐름이다.

```
구매(즉시구매)  →  결제(에스크로 보관)  →  판매자→검수센터 발송  →  검수센터 입고(수령)  →  검수
   CREATED          PAID                 SHIPPED_TO_INSPECTOR      UNDER_INSPECTION
                                                                        │
                                          ┌──────── 합격 ────────┐      └──── 불합격 ────┐
                                          ▼                              ▼
                            구매자에게 배송 + 판매자 정산            구매자 환불(에스크로 반환)
                                COMPLETED                              REFUNDED
```

- **에스크로**: 구매자 결제금은 판매자가 아니라 플랫폼이 보관. **검수 합격 시에만 판매자에게 정산**, 불합격 시 **구매자 환불**.
- **검수**: 플랫폼 운영자(검수자)가 백오피스에서 수령·판정. (검수 기준은 §7)
- 이 구조는 "정품·품질 보증"을 **기술적으로 강제**하는 장치다.

## 6. 범위 (성능·인프라 중심으로 재편)

> §0 목표에 맞춰 **성능·데이터·인프라**를 In, **제품 기능 심화**를 Out으로 둔다. 전체 작업은 [`BACKLOG.md`](./BACKLOG.md).

**완료 (MVP1·2)**
- 인증(JWT)·RBAC, 상품 CRUD·판매중, 구매·주문 7상태 상태머신(재고 동시성 락), 검수 수령/판정, 마이페이지·백오피스(기본)
- 결제(토스) 연동 — **결제는 여기서 종료**(정합성 추가 작업 안 함)

**핵심 (In — 기술 성장)**
- **대용량 데이터 + 조회 성능**: 대량 더미 시딩, N+1 제거·커서 페이지네이션, 인덱스 설계·쿼리 튜닝, **검색(색인/ES)**
- **캐싱·랭킹**: Redis 캐시(목록/상세) + 조회수·인기 랭킹 + 무효화 전략
- **비동기·처리량**: 도메인 이벤트 + 메시지 브로커(Kafka)
- **부하테스트·관측성**: k6, Prometheus/Grafana, 분산추적 → **병목→개선→재측정** 사이클(수치 기록)
- **AWS 배포**: Docker, CI/CD, EC2/RDS/ElastiCache/S3/ALB
- **이미지**: S3 업로드 + CDN

**범위 밖 (제품 기능 — 하지 않음)**
- 결제 정합성 심화(멱등성·보상·정산 원장), 정산/환불 자금 이동
- 검수 리포트 심화·검수비·반품/분쟁, 커뮤니티(후기·게시판·쿠폰·신고), 제품 알림, 배송사 연동, 운영 대시보드
- **직거래 · 채팅 · 사이즈**(삭제 확정), 경매·입찰, 수익 모델

## 7. 검수 기준 (카테고리별)

카테고리마다 검수 항목을 정의한다. **아래는 전자기기 예시** — 의류·잡화 등은 정품·상태·구성품 중심으로 별도 체크리스트를 둔다.

- **정품/모델 일치**: 제조사·모델명·저장용량이 등록 정보와 일치
- **작동/기능**: 전원, 화면, 터치, 카메라, 스피커/마이크, 버튼, 충전 등 정상 동작
- **외관 상태**: 액정 멍·긁힘·찍힘, 프레임 손상 (등급화 가능: S/A/B)
- **배터리 성능**: 성능 상태(%) 확인 (스마트폰)
- **이력 조회 (핵심)**: **IMEI/시리얼로 분실·도난 등록, 통신사 잠금, 약정/할부 잔여** 확인
- **침수 여부**: 침수 라벨/내부 부식
- **초기화/계정 해제**: 이전 사용자 계정(iCloud/구글) 로그아웃, 데이터 초기화

→ 불합격 사유는 위 항목 기준으로 구매자에게 투명하게 고지.

## 8. 포지셔닝 (경쟁 대비)

| 플랫폼 | 방식 | 우리와의 차이 |
| --- | --- | --- |
| 중고나라·번개장터 | 개인 직거래, 검수 없음 | 우리는 **강제 검수**로 사기·하자 원천 차단 |
| 당근마켓 | 지역 직거래·대면 | 우리는 **원격 + 품질 보증**(대면 신뢰 대신 검수 신뢰) |
| KREAM | 검수 기반이나 **패션/스니커즈/명품 중심** | 우리는 **중고 전자기기 특화**(IMEI·침수·잠금 등 전자기기 고유 검수) |

**차별 문장**: *"전자기기 중고, KREAM처럼 검수받고 안전하게."* — 검수 모델의 신뢰를 **전자기기 카테고리에 집중**해 KREAM과 겹치지 않는 자리를 잡는다.

## 9. 수익 모델 (초안)

- **판매 수수료**: 체결가의 일정 % (판매자 부담)
- **검수비**: 건당 정액 또는 카테고리별 (구매자 또는 판매자 부담 — 정책 결정 필요)
- (후순위) 광고/상단노출, 정품 인증 배지 프리미엄 등

## 10. 성공 지표 (기술 관점)

사용자 지표가 아니라 **성능·기술 개선**을 지표로 둔다.

- **응답시간(p95/p99)·처리량(TPS)** 의 개선 — 부하테스트 before/after
- 주요 조회(목록·검색) **쿼리 시간 / N+1 제거** 효과, 캐시 적중률
- 대용량(수십·수백만 행)에서의 조회 성능, 동시성 하 재고 정확성
- AWS 배포 자동화(CI/CD)·무중단/오토스케일 달성 여부
