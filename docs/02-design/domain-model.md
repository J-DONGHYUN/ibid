# 도메인 모델

용어 · 애그리게이트 · 상태 전이 · 불변식을 정한다. 요구사항(`requirements.md`)이
**무엇을 해야 하는가**라면 이 문서는 **무엇이 절대 깨지면 안 되는가**다.

## 용어

같은 개념을 문서 · 코드 · 테스트에서 같은 이름으로 부른다.
**코드 식별자 열이 정본이다.** 새 이름을 지어내지 않는다.

| 용어 | 코드 식별자 | 뜻 |
|---|---|---|
| 사용자 | `User` | 가입한 계정. 판매자이면서 구매 희망자일 수 있다 |
| 판매자 | `sellerId` | 상품을 올린 사용자. 계정 종류가 아니라 상품 기준의 역할이다 |
| 구매 희망자 | `buyerId` (채팅방) | 상품에서 판매자와의 채팅방을 연 사용자 |
| 채팅 상대 | — | 판매자 입장에서, 그 상품에 채팅방을 연 구매 희망자들 |
| 예약 상대 | `reservedBuyerId` | 판매자가 예약중으로 지정한 채팅 상대 한 명 |
| 거래 상대 | `soldBuyerId` | 판매자가 거래완료로 지정한 채팅 상대 한 명. 구매 내역의 주인 |
| 상품 상태 | `ProductStatus` | 판매중 `ON_SALE` · 예약중 `RESERVED` · 거래완료 `SOLD` |
| 전자기기 정보 | `DeviceSpec` | 카테고리 · 모델명 · 배터리 성능 · 구성품 · 하자 |
| 채팅방 | `ChatRoom` | (상품, 구매 희망자) 쌍 하나에 대한 1:1 대화 |
| 클라이언트 메시지 식별자 | `clientMessageId` | 재전송을 판별하려고 클라이언트가 메시지마다 붙이는 값 |

**현재 코드와 다른 것** — 코드의 `ProductStatus` 는 `PENDING` · `ON_SALE` · `SOLD_OUT` 이다.
이전 제품(재고 판매)의 상태이고, 위 표로 바꾼다 (`PD-01`).

## 애그리게이트

트랜잭션 하나는 애그리게이트 하나만 바꾼다. 다른 애그리게이트는 **id 로만 참조**한다
(연관관계 매핑을 걸지 않는다).

| 애그리게이트 | 루트 | 안에 포함 | 참조 (id) | 상태 |
|---|---|---|---|---|
| 사용자 | `User` | `Email` | — | 구현됨 |
| 상품 | `Product` | `ProductImage` · `DeviceSpec` · 거래 상태 | `sellerId` · `reservedBuyerId` · `soldBuyerId` | 변경 |
| 찜 | `ProductLike` | — | `userId` · `productId` | 구현됨 |
| 채팅방 | `ChatRoom` | 참여자별 읽음 위치 | `productId` · `sellerId` · `buyerId` | 신규 |
| 채팅 메시지 | `ChatMessage` | — | `roomId` · `senderId` | 신규 |
| 알림 | `Notification` | — | `userId` | 신규 |

- **찜을 상품에서 분리한 이유** — 찜은 상품의 생명주기와 무관하게 쌓이고, 상품을
  수정할 때마다 찜 목록을 불러올 이유가 없다
- **메시지를 채팅방에서 분리한 이유** — 메시지는 계속 늘어난다. 채팅방을 읽을 때마다
  메시지 전체를 불러오지 않는다
- **거래 상태를 상품 안에 둔 이유** — `ADR-0006`

## 상품 상태 전이

```
            reserve(채팅 상대)
   ON_SALE ────────────────────▶ RESERVED
   판매중  ◀──────────────────── 예약중
      │      cancelReservation()     │
      │                              │
      │ complete(채팅 상대)           │ complete(채팅 상대)
      ▼                              ▼
   ┌─────────────── SOLD ───────────────┐
   │             거래완료                 │
   │   어떤 상태로도 되돌아가지 않는다      │
   └─────────────────────────────────────┘
```

| 현재 \ 행위 | `reserve` | `cancelReservation` | `complete` | 수정 | 삭제 |
|---|---|---|---|---|---|
| `ON_SALE` | → `RESERVED` | 금지 | → `SOLD` | 가능 | 가능 |
| `RESERVED` | **금지** (해제 후 다시 예약) | → `ON_SALE` | → `SOLD` | 가능 | 가능 |
| `SOLD` | 금지 | 금지 | 금지 | 금지 | 가능 |

- [G] **허용된 전이와 금지된 전이를 모두 테스트한다.** 표의 칸 하나 = 테스트 하나
- 예약중에서 예약 상대를 바꾸려면 해제 후 다시 예약한다. "예약 상대 변경" 전이를 두지 않는다 —
  전이가 하나 늘 때마다 동시 요청 조합이 늘어난다

## 불변식

**강제 위치**가 가장 중요하다. 같은 규칙을 어디서 막는지 정하지 않으면 한 겹만 막거나,
세 곳에서 다르게 막는다.

- 엔티티 — 도메인 객체의 메서드가 막는다. 단위 테스트로 검증한다
- 서비스 — 여러 애그리게이트를 봐야 판정할 수 있다. 통합 테스트로 검증한다
- DB — 동시 요청은 애플리케이션 검사만으로 못 막는다. 제약으로 막고 위반을 409 로 바꾼다 (`ADR-0005`)

| ID | 불변식 | 강제 위치 | 관련 | 상태 |
|---|---|---|---|---|
| `I-01` | [G] 예약중이면 예약 상대가 정확히 한 명 있고, 예약중이 아니면 없다 | 엔티티 | `TR-01` · `TR-02` | 신규 |
| `I-02` | [G] 거래완료면 거래 상대가 정확히 한 명 있다 | 엔티티 | `TR-03` | 신규 |
| `I-03` | [G] 거래완료는 되돌릴 수 없다 | 엔티티 | `TR-03` | 신규 |
| `I-04` | 예약 상대와 거래 상대는 그 상품의 채팅 상대다 | 서비스 | `TR-01` · `TR-03` | 신규 |
| `I-05` | 판매자는 자기 상품의 구매 희망자가 될 수 없다 | 엔티티 | `CH-01` | 신규 |
| `I-06` | [G] 채팅방은 (상품, 구매 희망자)당 하나다 | **DB 유니크 제약** + 서비스 | `CH-01` | 신규 |
| `I-07` | [G] 메시지는 (채팅방, 클라이언트 메시지 식별자)당 하나다 | **DB 유니크 제약** | `CH-02` | 신규 |
| `I-08` | 채팅방 참여자는 판매자와 그 구매 희망자 둘뿐이다 | 엔티티 | `CH-02` · `CH-03` · `CH-04` | 신규 |
| `I-09` | 삭제된 상품의 채팅방에는 메시지를 보낼 수 없다 | 서비스 | `PD-06` | 신규 |
| `I-10` | [G] 찜은 (사용자, 상품)당 하나다 | **DB 유니크 제약** | `PD-07` | 구현됨 |
| `I-11` | 알림 실패가 메시지 전송을 실패시키지 않는다 | 트랜잭션 경계 (`ADR-0009`) | `NT-01` | 신규 |
| `I-12` | 상품의 상태 전이는 동시에 들어와도 표의 전이만 일어난다 | 동시성 제어 (`ADR-0008`) | `TR-01` · `TR-03` | 신규 |
