# ADR-0002 인증은 JWT 액세스 토큰 + 회전하는 리프레시 토큰

- 상태: 채택
- 관련: `AU-02` · `AU-03` · `AU-04`

## 맥락

API 서버가 세션 저장소 없이 요청마다 사용자를 식별해야 한다. 동시에 토큰을 탈취당했을 때
피해 기간을 줄이고, 로그아웃이 실제로 효력을 가져야 한다.

## 결정

- 액세스 토큰(짧은 만료)은 응답 본문으로, 리프레시 토큰(긴 만료)은 **httpOnly 쿠키**로 준다
- 리프레시 토큰은 **Redis 에 사용자당 하나** 저장하고, 재발급할 때마다 새 토큰으로 바꾼다(회전)
- 저장된 것과 다른 리프레시 토큰이 오면 실패한다. 로그아웃은 저장된 토큰을 지운다

## 대안

- **세션** — 서버 상태가 생기고, 실시간 채팅 서버와 인증 방식이 갈라진다
- **리프레시 토큰을 회전하지 않음** — 탈취된 토큰이 만료까지 계속 쓰인다
- **리프레시 토큰을 DB 에 저장** — 만료 정리를 직접 해야 한다. Redis 는 TTL 로 끝난다

## 결과

- Redis 가 없으면 로그인 · 재발급이 안 된다. 테스트는 Testcontainers Redis 를 띄운다
- **알려진 한계** — 검증(`RefreshTokenValidator`)과 교체(`RefreshTokenRotator`)가 원자적이지 않다.
  같은 리프레시 토큰으로 재발급이 동시에 두 번 오면 둘 다 통과하고, 나중에 저장된 토큰만 살아남는다.
  탭 두 개가 동시에 재발급하는 경우가 여기에 걸린다
- 실시간 채팅 연결의 인증도 같은 액세스 토큰으로 한다 (`ADR-0007` 에서 전달 방법을 정한다)
