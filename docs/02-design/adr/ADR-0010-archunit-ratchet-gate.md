# ADR-0010 아키텍처 규칙은 ArchUnit 게이트로 검사하고, 기존 위반은 동결한다

- 상태: 채택
- 관련: `03-convention/architecture.md` · `03-convention/code.md` · `03-convention/test.md` · `04-harness/harness.md`

## 맥락

컨벤션 문서에 `[G]` 로 표시한 규칙은 지금 **글로만** 있다. 에이전트는 대부분 지키지만, 컨텍스트가
길어지거나 급하면 빠뜨리고, 어겨도 아무 일이 일어나지 않는다. 사람이 리뷰에서 같은 지적을 반복하게 된다.

그런데 규칙을 게이트로 켜는 순간 **기존 코드가 이미 어기고 있다.** 2026-09-28 기준으로
`application` → `presentation` 10개 파일, `common` → 도메인 2개 파일, 주석 5개 파일 등이다.
이걸 다 고친 뒤에 게이트를 켜면, 고치는 동안에는 새 위반을 막을 수단이 없다.

## 결정

1. **계층 · 의존 규칙은 ArchUnit 으로 검사한다.** 테스트로 돌기 때문에 `./gradlew test` 와 CI 가 그대로 게이트가 된다
2. **ArchUnit 이 볼 수 없는 규칙은 소스 파일을 읽는 테스트로 검사한다.** 주석, Lombok `@Setter` · `@Data` 는
   컴파일된 클래스에 남지 않는다
3. **기존 위반은 동결한다 (래칫).** ArchUnit 의 `FreezingArchRule` 로 지금 위반을 저장소
   (`src/test/resources/archunit-store/`)에 기록하고, **새 위반만 실패**시킨다. 위반을 고치면 기록에서 빠지고,
   다시 늘어날 수 없다. 소스 검사는 테스트 안의 목록으로 같은 일을 하고, 고쳤는데 목록에 남아 있으면 실패시켜
   목록을 줄이게 한다
4. **게이트 테스트는 스프링 · Docker 없이 돈다.** `./gradlew architectureTest` 로 수 초 안에 끝난다 —
   루프가 자주 돌려야 하는 게이트는 빨라야 한다

## 대안

- **위반을 먼저 0으로 만들고 켠다** — 고치는 동안 새 위반이 계속 들어온다. 그리고 "지금 몇 개 남았나"가
  어디에도 기록되지 않는다
- **기존 위반을 `ignore` 로 제외** — 제외 목록은 줄어들지 않는다. 동결은 고치면 줄고 늘어날 수 없다
- **Checkstyle 로 주석 검사** — 도구가 하나 는다. 지금 필요한 소스 규칙은 두 개뿐이라 테스트 하나로 충분하다

## 결과

- 동결 목록(`archunit-store/`, 소스 검사의 목록)은 **남은 기술 부채의 목록**이다. 이 목록을 줄이는 것이
  루프의 첫 티켓이 된다
- 동결 목록을 손으로 늘리는 것은 게이트 우회다. 에이전트는 이 파일들을 고칠 때 사람에게 묻는다 (`.claude/settings.json`)
- **새 저장소 생성은 막아 둔다** (`freeze.store.default.allowStoreCreation=false`). 저장소가 없으면 게이트가
  조용히 전부 동결하는 대신 실패한다
- 아직 없는 도메인(`chat` · `trade` · `notification`)의 규칙은 대상 클래스가 없어 **빈 채로 통과한다.**
  도메인이 생기는 순간부터 검사가 실제로 시작된다 (`04-harness/harness.md` 알려진 구멍)
