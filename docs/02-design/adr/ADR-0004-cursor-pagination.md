# ADR-0004 목록은 커서 페이지네이션

- 상태: 채택
- 관련: `PD-03` · `PD-08` · `CH-04` · `CH-05` · `TR-04` · `TR-05`

## 맥락

상품 목록은 무한 스크롤이고, 채팅 메시지는 계속 쌓이며 위로 스크롤해 불러온다.
보는 동안 새 데이터가 앞에 끼어든다.

## 결정

모든 목록은 **커서 기반**으로 조회한다. 정렬 키(기본은 `id` 내림차순) 기준으로
"마지막으로 본 것보다 작은 것"을 가져온다. 응답에 다음 커서를 싣는다.

## 대안

- **OFFSET 페이지네이션** — 앞에 새 글이 끼면 다음 페이지에서 같은 글이 또 나온다.
  그리고 뒤로 갈수록 느려진다. 이전 측정에서 50만 행 뒤 OFFSET 조회가 약 100ms, 커서 조회가
  약 1ms 였다 (이전 문서 `PERF_SEEDING.md`, 커밋 `50b0bef`)

## 결과

- "3페이지로 바로 가기"는 만들 수 없다. 이 제품에는 필요 없다
- 정렬 키가 같은 행이 있으면 경계에서 누락 · 중복이 생긴다. **정렬 키는 유일해야 한다** —
  시각으로 정렬할 때는 `id` 를 보조 키로 붙인다. 테스트는 정렬 키가 같은 데이터를 일부러 만들어 경계를 본다
