# ADR-0003 공개 API 는 `@PublicApi` 로 연다

- 상태: 채택
- 관련: `PD-03` · `PD-04` · `02-design/api.md` 인증 등급

## 맥락

상품 목록 · 상세는 로그인 없이 보여야 하지만, 같은 경로 `/api/products/{id}` 의
`PATCH` · `DELETE` 는 판매자만 해야 한다. 인터셉터의 경로 제외 목록(`excludePathPatterns`)은
**HTTP 메서드를 구분하지 못한다.** `/api/products/**` 를 열면 수정 · 삭제까지 열린다.

## 결정

- 공개할 핸들러 메서드에 `@PublicApi` 를 붙인다. 인터셉터가 이 표시를 보고 판정한다
- `@PublicApi` 는 **토큰이 없으면 통과시키되, 토큰을 보냈다면 유효해야 한다.** 만료 · 위조는 401 —
  프론트의 "401 → 재발급 → 재시도" 흐름이 깨지지 않게 한다
- 공개 핸들러에서 로그인 사용자를 알아야 하면 `@LoginUser(required = false) UserInfo` 로 받는다
- 경로 목록 `WebConfig.PUBLIC_ENDPOINTS` 는 `/api/auth/**` 하나만 둔다

## 대안

- **경로 목록에 추가** — 위 이유로 기각. 에이전트가 가장 먼저 떠올리는 방법이라 명시한다
- **Spring Security 도입** — 메서드별 권한 설정은 되지만, 지금 필요한 것은 공개 · 로그인
  두 등급뿐이다. 의존성과 설정 비용이 더 크다

## 결과

- 공개 여부가 핸들러 옆에 보인다. 경로 목록과 컨트롤러를 오가며 대조하지 않는다
- 새 공개 API 를 만들 때 `@PublicApi` 를 빠뜨리면 401 이 난다 (닫힌 쪽으로 실패한다)
