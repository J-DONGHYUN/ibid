# ADR-0011 상품 삭제 방식

- 상태: **채택** (2026-10-02, 사람) — 소프트 삭제
- 관련: `PD-06` · `PD-08` · `CH-01` · `CH-05` · `TR-04` · `TR-05` · `I-09`

## 맥락

`PD-06` 의 검증 기준은 두 가지를 동시에 요구한다.

- 삭제한 상품은 목록 · 상세에 나오지 않는다
- **그 상품의 채팅방은 남아 있고**, 새 메시지는 보낼 수 없다

채팅방은 상품을 id 로 참조한다(`domain-model.md` 애그리게이트). 채팅방 목록(`CH-05`)은 방마다 상품 정보를 보여준다.
상품 행이 사라지면 남은 채팅방이 보여줄 상품이 없다. 그래서 "지운다"를 어떻게 표현할지 정해야 한다.

지금 코드는 **행을 실제로 지운다**(이미지는 S3 에서도 지운다). 이전 제품에는 채팅방이 없어서 문제가 없었다.

이 결정은 ADR 기준 셋에 모두 걸린다.

- **흔한 방법이 틀릴 수 있다** — 에이전트는 `@SQLDelete` 소프트 삭제를 먼저 떠올린다. 그러면 상품을 읽는 모든 조회에
  "삭제 안 된 것만" 조건이 걸리고, 거래 내역(`TR-05`)처럼 삭제된 상품도 보여야 하는 곳에서 조건을 벗겨야 한다
- **대안이 여럿이다**
- **되돌리기 비싸다** — 스키마와 모든 상품 조회가 바뀐다

## 선택지

| | A. 소프트 삭제 | B. 하드 삭제 + 채팅방에 상품 요약 복사 |
|---|---|---|
| 방식 | 상품에 `deletedAt` 을 두고 행은 남긴다 | 채팅방을 열 때 상품 제목 · 썸네일을 채팅방에 복사해 둔다. 상품은 실제로 지운다 |
| 목록 · 상세에서 숨기기 | 조회마다 조건이 필요 (전역 필터 or 쿼리마다) | 행이 없으니 자연히 안 나온다 |
| 남은 채팅방 | 상품 행을 그대로 읽는다 | 복사해 둔 요약을 읽는다 |
| 거래 내역 (`TR-04` · `TR-05`) | 삭제된 상품도 보여줄 수 있다 | 거래완료 상품을 지우면 내역이 사라진다 — 따로 막거나 복사해야 한다 |
| 이미지 | 남긴다 (나중에 정리) | S3 에서 지운다 |
| 비용 | 모든 상품 조회가 삭제 여부를 의식해야 한다 | 복사본이 원본과 달라질 수 있다 (수정 후 채팅방에는 옛 제목) |

## 결정 전에 정해야 할 질문

- **거래완료 상품을 삭제할 수 있나?** 할 수 있다면, 구매자의 구매 내역(`TR-05`)에 그 상품이 남아야 하나?
  — 요구사항에 아직 답이 없다. 답에 따라 B 의 비용이 크게 달라진다
- 삭제한 상품의 채팅방에서 상품 상세로 들어가면 무엇을 보여주나 (404 · "삭제된 상품" 안내)

## 결정 기준

- 삭제된 상품을 **보여줘야 하는 곳**이 많으면 A, 거의 없으면 B 가 단순하다
- 전역 필터(A)를 쓰면 "삭제된 것도 봐야 하는" 조회에서 필터를 끄는 방법이 필요하다. 이 우회가 늘어나면 A 가 불리하다

## 결정

**A. 소프트 삭제.** 상품에 `deletedAt` 을 두고 행은 남긴다.

- **거래완료 상품도 삭제할 수 있다.** 소프트 삭제라 지워도 행이 남아, 구매자의 구매 내역(`TR-05`)·판매 내역(`TR-04`)·채팅방(`CH-05`)은 그 상품을 그대로 읽는다. 판매자는 목록에서 치우고, 구매자 기록은 보존된다.
- **전역 필터(`@SQLRestriction`)를 쓰지 않는다.** 삭제분을 **보여줘야 하는 곳**(거래 내역·채팅방)과 **숨겨야 하는 곳**(목록 `PD-03`·상세 `PD-04`·관심목록 `PD-08`)이 공존하기 때문. 숨겨야 하는 조회에만 쿼리로 `deletedAt IS NULL` 을 건다. 전역 필터를 깔면 보여줘야 하는 곳에서 필터를 끄는 우회가 늘어 ADR 기준상 불리하다.
- **삭제된 상품의 상세 조회는 404** (`PRODUCT_NOT_FOUND`). `PD-06` 의 "목록·상세에 나오지 않는다" 를 지킨다. 채팅방에서 상세로 들어가면 "삭제된 상품" 으로 처리한다.
- **삭제된 상품의 채팅방에는 새 메시지를 보낼 수 없다**(`I-09`). 행이 남아 있으므로 전송 경로에서 `deletedAt` 을 확인해 막는다.
- 이미지는 당장 S3 에서 지우지 않는다(행이 남아 채팅방·내역이 썸네일을 읽을 수 있어야 한다). 정리는 나중에.

### 왜 B(하드 삭제 + 복사)가 아닌가
삭제된 상품을 **보여줘야 하는 곳이 여럿**(거래 내역·채팅방)이고, 거래완료 상품 삭제를 허용하면 B 는 내역을 따로 복사·보존해야 해 비용이 커진다. 복사본이 원본과 어긋나는 문제(수정 후 옛 제목)도 없다.

## 결과

- 상품을 읽는 조회는 **숨길지 보여줄지**를 자리마다 의식해야 한다 — 목록·상세·관심목록은 `deletedAt IS NULL`, 거래 내역·채팅방은 삭제분 포함.
- `ddl-auto: update` 라 `deletedAt` 컬럼은 nullable 로 추가된다 (기존 행은 null = 안 삭제됨).
- 구현은 `T-13`. 이 ADR 이 `채택` 이므로 시작할 수 있다.
