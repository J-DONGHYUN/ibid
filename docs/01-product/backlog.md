# 백로그

**무엇이 끝났고, 무엇이 진행 중이고, 무엇이 남았는지**의 정본이다. 티켓 하나 = 이슈 하나 = PR 하나.

## 쓰는 법

```
"T-04 시작"                  → 이 문서의 T-04 로 이슈를 만들고 루프를 시작한다
"삭제 예정 도메인 지우기 시작"   → 제목으로 찾아 같은 흐름
"티켓: 가격 정렬 추가하자"      → 이 문서에 없으면 티켓을 추가하고 같은 흐름
```

- **이슈는 미리 만들지 않는다.** 티켓을 시작할 때 이 문서의 목표 · 완료 조건으로 이슈를 만든다 (`ticket` 스킬 [0])
- **상태는 루프가 바꾼다.** 시작하면 `🔄` 와 이슈 번호를, PR 에서 `✅` 를 적는다. PR 이 머지되면 완료다
- 순서는 표의 위에서 아래가 기본이다. **선행이 `✅` 가 아니면 시작하지 않는다**

| 상태 | 뜻 |
|---|---|
| ⬜ | 할 일 |
| 🔄 | 진행 중 — 이슈가 있고 루프가 돌고 있다 |
| ✅ | 완료 — PR 머지 |
| ⏸ | 보류 — 이유를 상세에 적는다 |

종류가 **결정**인 티켓은 코드를 짜지 않는다. 에이전트가 선택지를 정리하고, **사람이 정하고**, ADR 을 `채택` 으로 바꾼다.

## 티켓 상세

이슈를 만들 때 **아래 내용이 그대로 이슈 본문이 된다.** 요구사항이 있는 티켓의 테스트 목록은 `requirements.md` 의 검증 기준에서 루프 [1] 이 수집한다.

### T-04 삭제 예정 도메인(order · payment · inspection)을 지운다

- **이슈 제목**: `chore: 삭제 예정 도메인(order · payment · inspection)을 지운다`
- **목표**: 이전 제품(검수 에스크로 배송 거래)의 도메인이다. 새 제품에 없고, 동결 기록의 대부분을 차지한다 (PRD 「현재 코드와의 차이」 · `NG-01` · `NG-02` · `NG-04`)
- **완료 조건**
  - order · payment · inspection 패키지와 그 테스트가 없다
  - 다른 코드가 이 셋을 참조하지 않는다 (`ControllerTestSupport` 의 mock 포함)
  - 전체 테스트가 통과한다
  - 동결 기록이 줄어들고, 늘어난 것은 없다 (`SourceRulesTest` 목록 포함)
  - `CLAUDE.md` 「이행기」 표와 `api.md` 「사라질 엔드포인트」 가 갱신된다
- **참고**
  - **첫 루프 티켓.** 계획 게시 후 `src/` 수정이 통과하는 경로를 여기서 처음 확인한다
  - 범위 밖: `frontend/` 의 주문 · 결제 화면, 상품의 재고(`ProductStockHandler`) — T-05

### T-05 상품에서 재고 · 배송비 · PENDING 을 지운다

- **이슈 제목**: `refactor: 상품에서 재고 · 배송비 · PENDING 을 지운다`
- **목표**: 직거래는 게시글 하나 = 물건 하나이고 배송이 없다 (`NG-02` · `NG-03`)
- **완료 조건**
  - `Product` 에 `stock` · `shippingFee` · `PENDING` 이 없다. 등록하면 바로 `ON_SALE` 이다
  - `ProductStockHandler` 와 재고 동시성 테스트가 정리된다
  - `PATCH /api/products/{id}/on-sale` 이 없다
  - `ErrorCode` 에 T-04 가 남긴 주문 · 결제 코드(`ORDER_*` 6개 · `PAYMENT_*` 4개)와 섹션 주석이 없다 (`INC-04`)
  - 재고 · 구매 관련 에러 코드 중 쓰이지 않게 된 것이 없다
  - 전체 테스트가 통과한다
- **참고**
  - 지우는 작업이라 **양방향으로 조사한다** — 누가 재고를 쓰나 + 재고 코드가 쓰던 공용 요소(에러 코드 · 설정)가 남나
  - `ddl-auto: update` 는 컬럼을 지우지 않는다 — 기존 DB 에는 NOT NULL 컬럼이 남는다 (`CLAUDE.md` 겪은 함정)
  - `RESERVED` · `SOLD` 전이는 T-21 · T-22 에서 만든다

### T-27 PR 전에 전체 빌드 통과를 강제한다

- **이슈 제목**: `chore: PR 전에 전체 빌드 통과를 강제한다`
- **목표**: 빠른 게이트는 구조 규칙만 본다. 기능 테스트가 깨진 채로 PR 이 올라갈 수 있다 — 지금은 스킬에 적은 부탁이다 (`loop.md` 「알려진 한계」)
- **완료 조건**

  - 탐침으로 막히는 경로와 통과하는 경로를 확인한다
- **참고**: **첫 루프(T-04)에서 실제로 새는지 먼저 본다.** 새면 사고 기록과 함께 진행한다

### T-28 테스트 이름의 요구사항 ID 를 검사하고 검증 기준 커버리지를 센다

- **이슈 제목**: `test: 테스트 이름의 요구사항 ID 를 검사하고 검증 기준 커버리지를 센다`
- **목표**: `@DisplayName("[TR-01] …")` 규칙에 게이트가 없다. 검증 기준마다 테스트가 있는지 셀 수 없다
- **완료 조건**
  - 새 테스트의 `@DisplayName` 이 요구사항 · 불변식 ID 로 시작하는지 게이트가 검사한다 (기존 테스트는 동결)

### T-29 Stop 훅이 커밋된 변경까지 보고 게이트를 돌리게 한다

- **이슈 제목**: `chore: Stop 훅이 커밋된 변경까지 보고 게이트를 돌리게 한다`
- **목표**: `gate-on-stop.sh` 가 커밋 안 된 변경만 봐서, 계획 한 줄마다 커밋하는 루프에서는 게이트를 한 번도 돌리지 않았다 (`INC-02`)
- **완료 조건**
  - "main 과 비교한 브랜치 변경 + 커밋 안 된 변경"에 `src/` · `build.gradle` 이 있으면 게이트를 돌린다
  - 같은 코드 상태(트리 해시)로 이미 통과했으면 다시 돌리지 않는다 — 문서만 고친 턴을 기다리게 하지 않는다
  - 탐침으로 확인한다: 커밋 후 끝내기 → 게이트가 돈다 · 같은 상태로 다시 끝내기 → 생략 · 규칙 위반 커밋 → 막는다
  - `harness.md` 「훅 생존 확인」 에 결과를 적는다
- **참고**: 훅 파일은 `ask` 라서 수정마다 승인이 뜬다. 루프가 루프를 고치는 첫 티켓이다

### T-30 guard-protected 의 오탐을 없앤다

- **이슈 제목**: `chore: guard-protected 의 오탐을 없앤다`
- **목표**: 리다이렉션(`2>&1`)과 heredoc 본문 속 단어 때문에 필요 없는 승인이 떴다 (`INC-03`)
- **완료 조건**
  - `2>&1` · `>&2` · `>/dev/null` 은 쓰기로 보지 않는다
  - heredoc 본문(`<<'EOF'` 아래)은 검사하지 않는다
  - **쓰기 대상**이 보호 경로일 때만 `ask` 한다
  - 탐침: INC-03 의 두 명령은 통과, 기존 막는 경로(`sed -i` · 리다이렉션 · `git checkout` 으로 보호 파일)는 여전히 `ask`
- **참고**: 막는 경로가 줄어들면 안 된다. 오탐 제거와 미탐 증가를 같이 확인한다

### T-31 PR 전에 자체 리뷰를 하고 최종 보고 양식을 정한다

- **이슈 제목**: `chore: PR 전에 자체 리뷰를 하고 최종 보고 양식을 정한다`
- **목표**: T-04 의 잔재(`INC-04`)는 루프 밖 독립 리뷰에서야 찾았다. 끝났을 때 보고도 요약뿐이라 사람이 무엇을 볼지 알기 어렵다
- **완료 조건**
  - `ticket` 스킬 [5] 에 **자체 리뷰** 단계가 있다 — 브랜치 변경을 리뷰하고, 찾은 것을 고치거나 안 고치는 이유를 적는다
  - PR 템플릿에 `🔍 리뷰` 절이 있다 (발견 · 조치)
  - 스킬 [6] 에 **최종 보고 양식**이 있다 — 한 일 · 리뷰 · 루프 기록 · 사람이 머지 전에 볼 곳
- **참고**: 자체 리뷰는 만든 눈으로 보는 리뷰라 한계가 있다. 루프 밖 독립 리뷰("PR #○○ 리뷰해줘")를 대신하지 않는다

### T-32 PR 이 머지되면 이슈가 닫히게 한다 · 결정

- **이슈 제목**: `docs: PR 이 머지되면 이슈가 닫히게 한다`
- **목표**: PR 이 develop 으로 머지돼 `Closes` 가 걸리지 않았다. 백로그 ✅ 와 이슈 상태가 갈라졌다 (`INC-05`)
- **완료 조건**
  - 방법을 정한다 — ① 저장소 기본 브랜치를 develop 으로 · ② 스킬에 "머지 후 이슈를 닫는다" 절차 · ③ PR 머지 시 이슈를 닫는 GitHub Action · ④ develop 을 없애고 main 하나로
  - 정한 방법이 적용되고, `loop.md` 에 이유가 적혀 있다
- **결정**: ④ **main 하나로** (사람이 골랐다). 이유와 기각한 대안은 `loop.md` 「브랜치」
- **참고**: 저장소 설정 · CI 를 바꾸는 일이라 **결정은 사람이 한다**
