# 요구사항 명세

기능을 ID 로 정의하고, 기능마다 **검증 기준**을 둔다.

**검증 기준이 곧 테스트 목록이다.** 루프에서 이 티켓이 통과해야 하는 테스트를 새로
설계하지 않고 여기서 수집한다. 검증 기준 한 줄 = 테스트 하나 이상.

검증 기준을 쓰는 규칙:

- 사람의 판단이 아니라 **테스트가 판정할 수 있는 문장**으로 쓴다. "빠르다" 가 아니라
  "한 번만 저장된다"
- **실패하는 경우를 반드시 적는다.** 에이전트는 성공 경로만 테스트하는 경향이 있다
- 에러 코드 이름은 적지 않는다. 코드가 정본이다 (`README.md` 정본 규칙)

`상태` 열 — `구현됨` 코드가 이미 기준을 만족 · `변경` 코드가 있지만 이 문서와 다름 ·
`신규` 코드가 없음. 무엇을 언제 하는지는 여기가 아니라 `backlog.md` 에서 본다.

## 인증 (AU)

| ID | 요구사항 | 검증 기준 | 상태 |
|---|---|---|---|
| `AU-01` | 회원가입 | 이메일 · 비밀번호 · 이름으로 가입한다 · 이메일 형식이 아니면 실패한다 · 이미 가입한 이메일이면 실패한다 · 이름이 4~8자가 아니면 실패한다 · 비밀번호가 4~12자가 아니면 실패한다 · 비밀번호는 원문으로 저장되지 않는다 | 구현됨 |
| `AU-02` | 로그인 | 맞는 이메일 · 비밀번호면 액세스 토큰과 리프레시 토큰을 발급한다 · 둘 중 하나라도 틀리면 실패하고, 어느 쪽이 틀렸는지 응답으로 구분되지 않는다 | 구현됨 |
| `AU-03` | 토큰 재발급 | 유효한 리프레시 토큰이면 새 토큰 쌍을 발급한다 · 한 번 쓴 리프레시 토큰으로 다시 요청하면 실패한다 · 만료되거나 위조된 토큰이면 실패한다 | 구현됨 |
| `AU-04` | 로그아웃 | 로그아웃한 리프레시 토큰으로는 재발급할 수 없다 | 구현됨 |

## 상품 · 찜 (PD)

| ID | 요구사항 | 검증 기준 | 상태 |
|---|---|---|---|
| `PD-01` | 상품 등록 | 제목(1~100자) · 설명(1~2000자) · 가격(1원 이상) · 상태(새상품 · 거의 새것 · 사용감 있음)로 등록한다 · **전자기기 정보**(카테고리 · 모델명 · 배터리 성능 · 구성품 · 하자)를 함께 받는다 · 배터리 성능은 0~100 사이만 받는다 · 하자는 비워도 된다 · 등록하면 판매중이다 · 수량과 배송비를 받지 않는다 (`NG-03` · `NG-02`) | 구현됨 |
| `PD-02` | 이미지 업로드 | 판매자만 이미지를 올릴 수 있다 · 업로드 URL 을 발급받아 스토리지에 직접 올린 뒤 확정한다 · 확정하지 않은 이미지는 상품에 붙지 않는다 | 구현됨 |
| `PD-03` | 상품 목록 | 최신순으로 커서 기반으로 조회한다 · 로그인하지 않아도 조회할 수 있다 · 거래완료 상품을 포함할지 거를지 고를 수 있다 · 목록에 상품 상태(판매중 · 예약중 · 거래완료)가 보인다 | 구현됨 |
| `PD-04` | 상품 상세 | 로그인하지 않아도 조회할 수 있다 · 전자기기 정보와 상품 상태가 보인다 · 판매자 본인이 보면 수정 · 삭제 · 거래 상태 변경이 가능하다고 표시된다 | 구현됨 |
| `PD-05` | 상품 수정 | 판매자 본인만 수정할 수 있다 · 거래완료 상품은 수정할 수 없다 | 구현됨 |
| `PD-06` | 상품 삭제 | 판매자 본인만 삭제할 수 있다 · 삭제한 상품은 목록 · 상세에 나오지 않는다 · 그 상품의 채팅방은 남아 있고, 새 메시지는 보낼 수 없다 · **삭제한 상품은 예약 · 예약 해제 · 거래완료 · 수정 · 이미지 변경을 할 수 없고 새 채팅방도 열 수 없다** | 변경 |
| `PD-07` | 찜 | 찜하기 · 찜 취소 · 찜 수와 내 찜 여부 조회를 한다 · 같은 상품을 두 번 찜할 수 없다 · **같은 사용자가 동시에 찜을 여러 번 요청해도 찜은 하나만 남는다** · 찜 취소는 여러 번 해도 결과가 같다 · **삭제된 상품은 찜할 수 없다 (이미 있는 찜은 취소할 수 있다)** | 변경 |
| `PD-08` | 관심 목록 | 내가 찜한 상품을 찜한 최신순으로 조회한다 · 삭제된 상품은 나오지 않는다 | 구현됨 |
| `PD-09` | 상품 조회수 | 상품 상세를 조회하면 조회수가 집계된다 · 방문자 식별자(쿠키)로 같은 방문자의 중복 조회를 거른다 · 로그인하지 않아도 집계된다 · 상세 응답에 집계된 조회수가 보인다 | 구현됨 |

## 채팅 (CH)

| ID | 요구사항 | 검증 기준 | 상태 |
|---|---|---|---|
| `CH-01` | 채팅방 열기 | 구매 희망자가 상품에서 판매자와의 채팅방을 연다 · **(상품, 구매 희망자) 쌍마다 채팅방은 하나다.** 이미 있으면 기존 방을 돌려준다 · **같은 쌍으로 동시에 요청해도 방은 하나만 생긴다** · 내 상품에는 채팅방을 열 수 없다 · 거래완료 · 삭제된 상품에는 새 채팅방을 열 수 없다 | 신규 |
| `CH-02` | 메시지 보내기 | 채팅방 참여자(판매자와 그 구매 희망자)만 보낼 수 있다 · 빈 메시지는 보낼 수 없다 · **같은 메시지를 재전송해도 한 번만 저장된다** (클라이언트가 붙인 메시지 식별자로 판정) | 구현됨 |
| `CH-03` | 실시간 수신 | 상대가 채팅방에 접속해 있으면 새로고침 없이 메시지를 받는다 · 한 채팅방 안에서 메시지는 보낸 순서대로 도착한다 · 참여자가 아니면 채팅방을 구독할 수 없다 | 구현됨 |
| `CH-04` | 메시지 목록 | 채팅방의 지난 메시지를 최신순으로 커서 기반으로 조회한다 · 참여자만 조회할 수 있다 | 구현됨 |
| `CH-05` | 내 채팅방 목록 | 내가 참여한 채팅방을 마지막 메시지 시각의 최신순으로 조회한다 · 방마다 상대, 상품, 마지막 메시지, 안 읽은 메시지 수가 보인다 | 구현됨 |
| `CH-06` | 읽음 처리 | 채팅방에 들어가면 그 방의 안 읽은 메시지 수가 0이 된다 · 상대 화면에 내가 어디까지 읽었는지 표시된다 | 구현됨 |
| `CH-07` | 상품별 채팅방 목록 | 판매자가 내 상품 하나에 열린 채팅방들을 조회한다 · 판매자 본인만 조회할 수 있다 · 예약 · 거래완료 상대를 여기서 고른다 | 구현됨 |

## 거래 (TR)

| ID | 요구사항 | 검증 기준 | 상태 |
|---|---|---|---|
| `TR-01` | 예약하기 | 판매자가 판매중인 상품을 채팅 상대 한 명에게 예약한다 · 판매자 본인만 할 수 있다 · 그 상품에 채팅방이 없는 사용자에게는 예약할 수 없다 · 예약중 · 거래완료 상품은 다시 예약할 수 없다 · **서로 다른 두 상대로 동시에 예약해도 한 명만 예약된다** · **삭제된 상품은 예약할 수 없다** | 구현됨 |
| `TR-02` | 예약 해제 | 판매자가 예약중인 상품을 판매중으로 되돌린다 · 예약 상대가 비워진다 · 판매자 본인만 할 수 있다 · **삭제된 상품의 예약은 해제할 수 없다** | 구현됨 |
| `TR-03` | 거래완료 | 판매자가 판매중 또는 예약중인 상품을 채팅 상대 한 명과 거래완료로 바꾼다 · 거래완료 상품은 다시 판매중 · 예약중으로 되돌릴 수 없다 · **예약 해제와 거래완료가 동시에 들어와도 상태가 어긋나지 않는다** · **삭제된 상품은 거래완료할 수 없다** | 구현됨 |
| `TR-04` | 판매 내역 | 내가 올린 상품을 상태별(판매중 · 예약중 · 거래완료)로 조회한다 | 구현됨 |
| `TR-05` | 구매 내역 | 내가 거래완료 상대로 지정된 상품을 조회한다 | 구현됨 |

## 알림 (NT)

|---|---|---|---|

## 이 문서에 없는 것

- **이전 제품의 기능**(주문 · 결제 · 검수)은 요구사항이 아니다. `NG-01` · `NG-02` · `NG-04`
- **남은 결정**(동네 · 후기 · 가격 제안)은 PRD 에서 정해지면 ID 를 새로 붙여 추가한다
