# 개발 백로그 — 성능·인프라 중심 (Development Backlog)

> **목표**: 기술적 성장의 증명 — **대용량 데이터 가정 + 부하테스트 기반 성능 개선 + AWS 인프라**. ([`PRODUCT_PLAN.md`](./PRODUCT_PLAN.md) §0)
> 도메인(검수 에스크로 전자기기 마켓)은 **그릇**이다. 제품 기능 심화·사용자 유치는 목표가 아니다.
> **결제는 종료**(정합성 추가 안 함). **RBAC·동시성 등 기술 기반기는 유지.** 2인 분담.

## 범례
- 우선순위: `P0` 지금 축의 핵심 / `P1` 필요 / `P2` 여유 시
- 유형: `성능`·`인프라`·`기반`(안정화/보안) · **모든 성능 작업은 "측정→개선→재측정" 수치 기록이 완료 조건**

## 2인 분담 (성능 축 / 인프라 축)

### Track A — "데이터 & 성능"
- **Epic 1**(대용량·검색), **Epic 2**(캐싱·랭킹), **Epic 4**(부하테스트·관측성)
- 성격: 쿼리 튜닝·인덱스·캐시·측정→개선 — **성능 깊이**

### Track B — "인프라 & 비동기"
- **Epic 3**(이벤트·Kafka), **Epic 5**(AWS·CI/CD), **Epic 6**(이미지·CDN)
- 성격: 클라우드·컨테이너·비동기·파일 — **인프라 폭**

> 공유 지점: 부하테스트(LOAD-1)/관측성은 **양쪽 결과물 대상**으로 함께. AWS 배포 환경(RDS/Redis)은 Track A의 성능작업 전제라 **초기에 같이 세팅**.
