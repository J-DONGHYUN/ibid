# domain 계층

**의존 그래프의 끝이다.** Spring 에도, 같은 도메인의 다른 계층에도 의존하지 않는다
(`common.exception` · `jakarta.persistence` 만 허용). 그래야 스프링 없이 단위 테스트한다.

- **상태 전이 규칙은 엔티티 메서드 안에 둔다.** 서비스에서 `status` 필드를 직접 바꾸지 않는다.
  `Product` 의 전이는 `docs/02-design/domain-model.md` 「상품 상태 전이」 표가 정본이다
- 전이 메서드를 새로 만들거나 바꾸면 **표의 모든 칸(허용 · 금지)을 테스트한다**
- 생성은 정적 팩토리 `create(...)`. 생성 시 불변식을 검증한다
- `@Setter` · `@Data` 를 쓰지 않는다
- 다른 애그리게이트는 id 로만 참조한다. `@ManyToOne` 으로 다른 애그리게이트를 걸지 않는다
- 여러 애그리게이트를 봐야 하는 판정은 여기 두지 않는다 → 그 둘을 볼 수 있는 도메인의 `application`

에이전트가 자주 틀리는 것 — **"예약 상대 변경" 같은 전이를 편의로 추가하는 것.**
전이 하나가 늘면 동시 요청 조합이 늘어난다. 표에 없는 전이는 만들지 않는다.
